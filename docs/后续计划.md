# 后续计划

> 下面各项代码均已实现。保留这些文字作为设计依据和排障参考，不再是待办清单。

## 开机自启动

在设置里增加「开机自启动」开关，默认关闭。

- 开启时写入当前用户的 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，值为 `AdbDeviceVitals.exe` 的完整路径。不请求管理员权限。这是 Windows 的启动登记机制，不算用户配置。
- 关闭时删除该项。
- 程序路径变化后，下次启动时按 `settings.json` 里的开关重新登记，不用等用户再保存一次设置。
- 自启动后进入系统托盘，不弹出主窗口。已有实例在运行时，沿用现有单实例逻辑，不再启动第二份进程。

开关与现有 ADB 目录一起保存在 `~/adb-device-vitals/settings.json`，详见文末「实现说明：配置文件」。

## 启动后自动开启 USB 网络共享

程序启动后（含开机自启动和手动启动）自动查找设备，并在 USB 网络共享未开启时尝试打开。该行为单独做成设置项，默认关闭，避免未经选择就改手机的 USB 模式。

流程：

1. 沿用现有逻辑定位 `adb.exe`，执行 `adb devices`，只处理状态为 `device` 的已授权设备。多台在线时按设置里指定的目标设备处理，详见文末「实现说明：多设备下的目标设备」。
2. 读取 `dumpsys tethering`。已有 `rndis*` 或 `ncm*` 处于 `TetheredState` 且 `lastError = 0` 时，视为已开启，不再切换 USB 功能。
3. 未开启时执行 `svc usb setFunctions rndis,adb`，保留 ADB，避免调试连接被切掉。（实际实现只下发 `rndis`，差异与原因见文末「实现说明」）
4. USB 重新枚举后等待设备重新出现，再次读取 `dumpsys tethering` 确认结果。
5. 登录后手机或 ADB 可能尚未就绪。在一段时间内按间隔重试查找和开启，成功、用户关闭该设置，或进程退出后停止。

失败时只在界面和托盘提示原因，不反复改 USB 模式：

- 找不到 `adb.exe`
- 没有设备，或设备为 `unauthorized`
- `svc usb setFunctions` 执行失败
- 命令成功但共享仍未进入 `TetheredState`（部分厂商不会因此拉起 NAT/DHCP，或运营商禁止网络共享）

已开启时不做开关切换。关闭共享是通过主窗口「USB 共享」开关手动完成的（`svc usb setFunctions mtp`），不属于自动开启流程。

## 实现说明：USB 功能组合保持 `rndis`

上一节流程的第 3 步，实际实现为 `svc usb setFunctions rndis`，不显式带 adb。**这个差异是有意保留的，现状不做改动。**

原因：

- `setFunctions` 是"替换整个组合"语义，按字面执行时不含 adb 就会摘掉调试通道。但在验证机型（小米 M2102K1AC）上下发 `rndis` 后，`getprop sys.usb.state` 仍为 `rndis,adb`，系统自己把 adb 并了回来，调试连接没有中断。
- 因此在验证机型上，显式写 `rndis,adb` 收益为零，反而多一条可能因厂商实现差异而失败的命令，故维持 `rndis`。
- 这个做法依赖 ROM 行为，不是协议保证。若某机型严格按 AOSP 语义只保留 `rndis`，切换后 ADB 会掉线：`ConfirmAsync` 等不到设备重新上线，会把已经成功的切换报成「USB 功能已切换，但网络共享未进入 TetheredState」，界面上也无法再用 `setFunctions mtp` 关闭共享，只能到手机上操作。遇到这种机型时，再把 `EnableFunctionCommand` 改回 `svc usb setFunctions rndis,adb`。
- 另外，`setFunctions` 只改运行时组合，不写入 `persist.sys.usb.config`。拔插数据线或重启手机后，USB 功能回到系统持久化的组合（通常只含 adb 或 `mtp,adb`），共享不会自动恢复，因此"切完靠 USB 重枚举再连回来"并不成立，不能当作恢复手段。

## 启动后自动开启电脑热点

把已经进到电脑里的手机网络，再用 Wi-Fi 分给其他设备。设置项 `AutoStartPcHotspot` 默认关闭，与 ADB 目录一起保存在 `settings.json`。

流程：

1. 开机链路在 USB 网络共享那一步落定后触发；若「启动后自动开启 USB 网络共享」未开启，则启动时直接触发。
2. 遍历 `NetworkInformation.GetConnectionProfiles()`，按网卡驱动描述匹配手机共享出来的网卡（`Remote NDIS Compatible Device`、`NCM` 等），取连通性最高的一条作为上游。
3. 上游还没拿到地址时按 3 秒间隔重试，最长 120 秒；超时只提示一次，不无限重试。
4. 以该配置文件创建 `NetworkOperatorTetheringManager`，先用 `GetTetheringCapabilityFromConnectionProfile` 检查系统是否允许，再 `StartTetheringAsync`，最后确认 `TetheringOperationalState` 落到 `On`。

**不能用默认路由当上游**：`GetInternetConnectionProfile()` 返回的是默认路由，电脑同时连着别的网络时（比如办公室 Wi-Fi），热点会把那个网络共享出去，而不是手机流量。必须按网卡描述找 RNDIS/NCM 那块网卡。

实现细节与踩到的坑：

- WinRT 全部走反射，不引用 `System.Runtime.WindowsRuntime`，以保住"只用系统自带 csc 编译、零 NuGet"的构建方式。`IAsyncOperation<T>` 在这种条件下无法 `await`，改为轮询 `IAsyncInfo.Status`（`0=Started`、`1=Completed`、`2=Canceled`、`3=Error`）后再取结果。
- `TetheringOperationalState` 的取值是 `Unknown = 0`、`On = 1`、`Off = 2`、`InTransition = 3`，**不是**按名字直觉排列。最初按 `Off = 0` 映射，结果关掉的热点被读成"切换中"，一直报"热点仍在运行"。
- 异步操作在运行时是 `__ComObject`，`GetType()` 上找不到 `GetResults`，必须用方法声明的返回类型（`IAsyncOperation<T>`）去反射。
- 读状态要重新创建 manager，复用同一个对象拿到的是旧值。
- 系统从 `InTransition` 落到 `On` / `Off` 通常一秒内完成，确认窗口取 20 秒、间隔 1 秒即可。

界面把它单独放在底部一行「电脑热点」。上面那张「网络共享」卡片读的是手机侧状态（`dumpsys tethering` / `dumpsys wifi`），两者含义不同，混在一起容易看错。

热点由 Windows 的 ICS 服务提供，客户端会拿到 `192.168.137.x` 的地址。程序退出不会关闭热点。

## 实现说明：多设备下的目标设备

同时连接多台 Android 设备时，原来的 `FirstAuthorized(devices)`（取列表第一台已授权设备）会埋一个隐患：状态卡片看着 A 手机，USB 共享开关却可能切到 B 手机，而 `setFunctions` 改的是那台手机的 USB 功能组合。因此改为统一由 `Services/DeviceSelection.cs` 的纯函数 `Resolve(devices, preferredSerial)` 决定目标，**监控采集（`DeviceMonitor`）和共享开关（`UsbTetheringService`）都调用它**，保证两处看到的是同一台设备。

判定规则：

| 情况 | 结果 |
|---|---|
| 没有已授权设备 | 提示授权 USB 调试 / 未找到设备 |
| 未记录序列号，只有 1 台 | 直接用它（保持零配置的即插即用） |
| 未记录序列号，多台 | 返回「请在设置中指定用于网络共享的设备」 |
| 记录了序列号，且在线已授权 | 精确锁定该设备，与列表顺序无关 |
| 记录了序列号，但当前不在已授权列表中 | 返回「预设的设备（xxx）未连接，请在设置中从当前设备列表重新选择」 |

最后一行是**刻意不降级**：即使当前只剩一台别的手机，也不会自动改用那台。换手机、换 USB 口、设备临时离线这些情况都应该由人确认，而不是猜。设备在线但状态是 `unauthorized` / `offline` 同样算「不在列表」。

设置项 `TargetDeviceSerial` 与其他配置一起存在 `settings.json`，值为字符串，空表示自动模式；读取时用 `DeviceSelection.IsValidSerial` 校验，与 `AdbClient.RunShellAsync` 拼 `-s <serial>` 前的正则一致，避免手改配置文件写进非法命令。

各条路径上的表现：

- **设置页**：下拉框列出「自动选择」+ 当前已授权设备；若记录的设备不在列表，额外追加一项 `⚠ 预设设备 xxx 未连接，请重新选择` 并默认选中，下方橙红色说明；此时保存会被拦下，必须先重新选。「刷新列表」按钮可在不关窗口的情况下重新读取 `adb devices`（改了 ADB 目录需先保存、重开设置）。
- **主窗口**：`DeviceSnapshot` 增加 `NeedsDeviceSelection` / `PreferredSerialMissing`。顶部状态显示短提示并支持点击打开设置（空间有限，完整原因放托盘气泡）；USB 共享开关置灰。
- **自动开启共享**：`EnsureCoreAsync` 把「目标设备未就绪」当作等待原因，在 3 分钟 discovery 窗口内继续等，不会顺手用列表里的其它设备；超时后把提示显示出来。
- **手动开关共享**：直接返回提示，不执行 `setFunctions`。

`ConfirmAsync` 仍按命令下发时的序列号判断设备是否重新上线，切换 USB 功能后即使旁边还有别的手机在线，也不会把确认结果算到它们头上。

## 实现说明：配置文件

配置不再放 `HKCU\Software\AdbDeviceVitals`，改为 `~/adb-device-vitals/settings.json`（通过 `Environment.SpecialFolder.UserProfile` 解析，不是 exe 所在目录）。字段沿用旧注册表值名，迁移时无需映射：`AdbDirectory`、`TargetDeviceSerial`、`RunAtStartup`、`AutoEnableUsbTethering`、`AutoStartPcHotspot`、`LastUpdateCheckUtc`，外加一个 `schema` 版本号。后来新增的 `AutoRecoverUsbTethering`（默认关闭）、`SmsSyncEnabled`（默认关闭）、`SmsToastEnabled`（默认开启）与 `SmsSenderFilter`（默认为空）不在旧键里，旧文件缺字段时按各自的默认值处理。

- **格式**：手写极简 JSON 编解码，放在 `Services/SettingsFile.cs` 里做纯函数。项目靠系统自带编译器、零 NuGet 构建，不能为一个配置文件引入 JSON 库或多一条程序集引用；做法与 `UpdateChecker` 用正则读 GitHub JSON 一致。解析是宽容的：未知字段忽略、写坏的字段跳过，坏一项不丢整份配置。
- **缓存**：`AppSettings` 保留全部静态属性的签名，内部改为带锁的内存快照。轮询每 2.5 秒读一次 `TargetDeviceSerial`，USB 共享等待循环也反复读 `AutoEnableUsbTethering`，getter 绝不能碰磁盘。只在启动（`Initialize`）、打开设置（`Reload`）和保存（`Save` / 属性 setter）时读写文件；写盘成功后才更新缓存，所以设置页保存后 `_adb.ReloadPath()` 立即拿到新值。
- **原子写**：同目录 `settings.json.tmp` → `File.Replace`（首次创建则 `File.Move`），UTF-8 无 BOM。设置页原来是逐个属性写 5 次注册表，现在一次 `Save(SettingsData)` 写整份，不留下中间状态。写失败抛给设置页提示，内存保持旧值；`LastUpdateCheckUtc` 写失败仍静默。
- **一次性迁移**：文件不存在时读旧键生成文件，成功后在旧键写 `MigratedTo` 标记。**标记是关键**：否则用户删掉 `settings.json` 想重置时，下次启动又会被旧注册表值灌回来。旧值本身不删，回滚到 0.0.6 仍可用。迁移时对 `TargetDeviceSerial` 沿用 `IsValidSerial` 校验。
- **自愈与容错**：启动时若 `RunAtStartup` 为 true，会重新登记一次 Run 项，顺带修好 exe 换路径或 Run 项被清理的情况。目录不可写、文件读不了时退回内存默认值并由托盘提示一次，不阻断启动。
- **保留在注册表的两样东西**：`HKCU\...\Run\AdbDeviceVitals` 是 Windows 的启动登记（`--startup` 靠命令行参数判断，不读注册表）；旧键里的 `MigratedTo` 是迁移状态。两者都不是用户配置。
- **不动的地方**：CSV 日志与 `tether.log` 仍在 `%LOCALAPPDATA%\AdbDeviceVitals\logs`。CI 的 zip 里本来就只有 exe、README、LICENSE，配置文件由程序首次运行生成，发布流程不需要改；自更新替换 exe 后重启，配置天然保留。

## 实现说明：USB 网络共享掉线自动恢复

设置项 `AutoRecoverUsbTethering`，默认关闭，保存在 `settings.json`。判定逻辑放在 `Services/UsbTetherWatchdog.cs`，是纯状态机：不碰 ADB、不读系统时间，时间由调用方传入，便于在 `ParserTests` 里推时钟验证。

- **数据来源**：复用 `DeviceMonitor` 每 2.5 秒一轮的 `DeviceSnapshot.UsbTetheringActive`（`dumpsys tethering` 每 12 秒真正读一次，命令失败时沿用上一轮的值，不会把「读不到」当成「掉线」）。不新增定时器，也不额外下发探测命令。
- **状态门槛**：`_wasActive` 记录是否观察到过共享开启，避免程序一启动就把用户本来关着的共享打开；`AutoEnableUsbTethering` 打开时通过 `assumeWasActive` 放宽这个门槛，启动瞬间的掉线也能兜住。
- **三级节流**：`CheckInterval = 20s` 限制判定频率，`ConfirmWindow = 20s` 要求连续读到未开启，`RetryCooldown = 60s` 限制失败重试。切换 USB 功能会让 ADB 重枚举，频繁重试只会让链路更不稳。
- **并发**：`MainForm` 把 `_usbTetherRunning`（开机自动开启）、`_tetherSwitchBusy`（手动开关）、`_usbWatchdogRunning`（守护自身）合并成 busy 传给状态机；恢复任务用独立的 `CancellationTokenSource`，退出或手动切换时取消。
- **复用开启链路**：调用 `UsbTetheringService.SetEnabledAsync(true, ...)`，它内部先 probe，返回 `AlreadyActive` 时不会重复下发 `setFunctions`；`ConfirmAsync` 仍按命令下发时的序列号确认设备重新上线，多设备场景不会算到旁边的手机上。
- **手动意图**：`NoteManualOff` / `NoteManualOn` 抑制守护；设置页把开关从关改成开时解除抑制。托盘提示：开始尝试与恢复成功各一次，失败只在第一次弹气泡，状态栏始终显示最新结果。
- **不碰热点链路**：守护结果不走 `StartPcHotspotIfPending`，自动开热点仍然只在开机链路里触发一次。

## 实现说明：短信通知同步

需求口径：**应用打开之后开始监听，打开之前的短信不管**；界面上要有近期短信列表。不要求实时推送。

- **方案选择**：ADB 增量轮询 `content://sms/inbox`，不装手机 App、不 Root、不加依赖。对比过 `dumpsys notification --noredact`（通知被划掉就漏、会顺带读到其它 App 的正文、格式随 ROM 变）和手机端 `SMS_RECEIVED` 广播（要第二个工程、国产 ROM 保活成本高），都不如直接读短信库可靠。
- **实测口径**（验证机型 M2102K1AC / Android 14 / MIUI V816）：`cmd appops get com.android.shell READ_SMS` 默认 allow；`--projection` 用冒号分隔，`--sort '_id DESC'`、`--where 'date>N'` 均生效，**`--limit` 不支持**（报 Unsupported argument）；空结果输出 `No result found.`；`adb shell date +%s` 可作时间基线。Windows 侧把 where 用单引号包住，`>` 不会被当成重定向（用 C# `AdbClient.RunShellAsync` 原样跑过）。
- **基线而不是 max id**：用户明确不看历史，用手机时钟做基线最干净，启动时一次 `date +%s` 就够，不必为了拿最大 `_id` 去翻近万行收件箱。每轮查 `date > 基线`，游标推进到「本轮最大 date − 2 秒」，靠 `_id` 集合去重吸收重叠窗口；游标只前进不后退。
- **解析**：`body` 放在 `--projection` 最后，按 `Row: <序号>` 分段，段内除首行外都并回正文（实测 15 条记录占 28 个物理行，确有正文换行）；`IndexOf("body=")` 之后整段算正文，只有前面的 `_id/address/date` 按逗号切。没有 `_id` 的行直接丢，避免反复弹同一条通知。`Parsing/SmsRowParser.cs` 是纯函数，测试里用合成数据覆盖逗号、等号、换行、权限错误和空结果。
- **节流与并发**：挂在 `MainForm` 每 2.5 秒的采集上，`SmsInboxService` 内部节流到 10 秒并用 `_running` 挡并发；调用处不 await，避免一条 content query 拖慢整轮状态刷新。设备序列号变化时重建基线并清空列表，不把两台手机的短信混在一起。多设备沿用 `TargetDeviceSerial` 的仲裁结果。
- **存储与隐私**：`SmsMessage` 只存在 `_messages` 列表（上限 100 条）和 `_seen` 去重集合里，重启即清空。不进 `DeviceSnapshot`，不写 CSV / `tether.log`，不上传。主窗口预览行与托盘/Toast 提醒都不带正文，`SmsForm` 默认也不显示正文；「复制正文 / 复制验证码」会进剪贴板，Toast 会进通知中心历史，README 已写明。
- **开关语义**：`SmsSyncEnabled` **默认关闭**（旧配置文件缺该字段也按关闭处理），关闭时连基线都不建立；从关改成开时 `ResetBaseline()` 重建，不补报关闭期间的短信，但已收到的列表保留。
- **正文按需展开**：`SmsForm` 的 `_showBody` 默认 false，窗口一关就复位，不写进配置。列表内容列用打码占位符，详情框只给发件人和时间；点「显示正文」才把预览列、详情框和「复制正文」放开。含验证码的消息在隐藏状态下只标 `[含验证码]`，不显示码值。状态文字长度会变，每次改状态都要 `PositionStatus()` 重新靠右，否则会跑出窗口（渲染探针抓到过）。
- **验证码**：`Parsing/SmsCodeExtractor.cs` 纯函数，先找「验证码 / code / OTP」等关键词后 4–8 位数字，再看全文是否恰好只有一个独立 4–6 位数字块；余额、订单、日期类关键词直接排除。`SmsForm` 的「复制验证码」与主窗口托盘菜单「复制最新验证码」只把码写进剪贴板，不需要展开正文，也不在提醒文案里带码值。
- **发件人过滤**：`SmsSenderFilter` 字段（逗号、分号、竖线、空格分隔）经 `Parsing/SmsSenderFilter.cs` 的 `ShouldNotify` 只决定**要不要弹提醒**，不影响采集与列表内容，留空表示全部提醒。过滤纯函数有单测覆盖。
- **Windows 通知**：`Services/WindowsToastService.cs` 反射调用 WinRT `ToastNotificationManager` / `ToastNotification` / `XmlDocument`，`Program.Main` 在建窗口前用 `SetCurrentProcessExplicitAppUserModelID` 设置 AUMID。运行时对象是 `__ComObject`，`Show` 要从 `CreateToastNotifier` 声明的返回类型上找（与热点服务同一个坑）。不做点击激活（需要 COM 激活器与快捷方式），点击请用托盘菜单。任何一步失败就置 `_unavailable` 并永久回退托盘气泡，避免每条短信都抛异常；`SmsToastEnabled` 可在设置里关掉。本机探针实测 `CanTry=True`、`TryShow=True`。
- **失败处理**：`IsPermissionDenied` 单独识别 `Permission Denial` / `READ_SMS` / `SecurityException`，给中文排障提示并在托盘提醒一次；命令失败、超时、手机时钟读不到都走同一条错误通道，不会静默变成「没有新短信」。成功后清除错误标记，下次失败还能再提示。
- **验证**：`ParserTests` 有解析与配置断言，主窗口、设置页、短信窗口都有渲染截图；另用只读探针在真机上跑过「建立基线 → 增量读 15 条 → 下一轮去重 0 条 → 开关关闭」全链路，探针不输出任何短信正文。
